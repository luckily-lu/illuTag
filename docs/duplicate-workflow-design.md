# 重复检索：直接替代证据与统一整理

用户于2026-10-19确认，1.11.0实现。当前策略为`illuTag-replacement-v2`。

## 使用流程

一次点击“查找可整理副本”，一个任务自动检查／复用指纹、召回候选、验证原图、生成全量计划。完成后只有“可回收／保留”两个处理状态，主数字按图片唯一计数。组数只说明可查看的上下文，不与净回收数量混算。

保留包含最终基准、人工保护、未通过验证、证据不足和未发现副本。未通过同图验证不能描述成已确认内容不同。按证据查看属于可选浏览入口，人工审查不是统一整理的前置步骤。

每张回收目标必须直接关联一个仍然保留的文件。候选组不是同一作品家族，相似关系不能传递。候选验证失败后仍可成为新的参考，解决A与B有变化、C是B副本时漏掉B—C的问题。一次失败只约束该对，不全局禁止该图片寻找其它副本。人工保留继续跨组生效。

## 自动准入与建议

- 文件同一：大小、SHA-256、逐字节一致。原有稳定随机保留选择在当前计划内保持。
- 完整像素同一：当前限定实际格式为静态PNG／JPEG、RGB8、32MP以内和128MiB解码上限；完整解码、不缩小、不白底合成。朝向校正后像素完全一致，且受保护容器信息相同。PNG附属块、JPEG各扫描段间的APP／COM以及文件尾附加数据均检查。透明度、高位深、复杂格式、不同受保护信息均保留。
- 有损建议：有限全图重采样（Triangle／CatmullRom／Lanczos3）与局部／多尺度残差检查。当前`LOSSY_CALIBRATED=false`，用户没有已标注真实样本，不能自动回收。建议提供可选人工处理通道，不能把合成测试当真实误判率。

有损比较不拟合局部形变或任意调色。缩到较小图一致不能证明高分辨率细节一致。大小、像素面积仅用于比较顺序；方向缺乏可靠证据时保留双方。没有因这版改造新增模型或模型索引。

## 发布、缓存与执行

主库仍是schema 3。指纹和字节证明复用；旧v1有损pass/fail不能作为v2自动回收证据。v2缓存绑定两端源签名、文件哈希和策略版本，保存具体原因和有界诊断摘要，不保存原图／完整差分图。无法确认不永久缓存。

候选使用pHash邻域与信息量足够的较严格dHash邻域并集，颜色参与辅助判断而非旧版全部同时过关。低信息图仅在完整指纹相同的范围验证像素同一。候选过密明确部分完成，不改为全库两两矩阵。

每张候选仅保留有限的未通过上下文，有更有用的有损建议可替换早先的失败说明。正向证据始终记录。图片对缓存按块淘汰，容量约65,536条，允许一个1024条提交周期的余量；淘汰后执行可重新验证，绝不能跳过证明。整体缓存、WAL预算512MiB和磁盘2GiB预留继续执行。

新代先在隔离行中计算，生成计划后在短事务内切换发布指针。失败／取消不替换上次完整结果，已提交图片对证据可复用。后台期间的人工选择通过全局版本检查合并，必要时只重建计划。旧版预览不能绕过v2验证继续执行；成功历史仍可撤销。

操作类别先物化符合条件的组，再定位成员与身份，不逐图片重扫全部组。检索中发现源失效会改变成员令牌，不能被最终发布清除。原始尺寸一致的比较借用已解码像素，避免再复制两份原图。

统一回收覆盖全部计划，不限于前端已加载组。执行前核对源、最终保留图、内容哈希和当前替代证据；明确人工标记单独记录。默认应用回收站保留原文件与元数据，支持整批撤销。完整备份／目录迁移不携带派生缓存，撤销日志保持独立。

## 验证与后续校准

合成回归覆盖A—B—C残余关系、跨组非传递、真实双连接、旧缓存隔离、透明／元数据保护、取消／失败发布、人工选择合并、全量整理与撤销。headless脚本为`scripts/refactor/duplicate-evidence-headless-qa.mjs`，仅生成SVG，不启动正式程序。

未来启用有损自动准入须收集真实正负样本，按作品家族拆分开发／盲测，测召回、回收准确率、灰区与资源成本。样本内零错误也不证明全库零风险。规范或准入范围改变必须增加版本，不能静默复用旧证明。
