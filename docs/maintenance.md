# illuTag 1.13.2 维护指南

当前版本使用 Vue 3、TypeScript、Tauri 2、Rust、SQLite schema 3 与 Python ONNX。
1.13.0采用全库宽筛、内容收紧、严格像素确认三轮连续检索。完全相同与近似分别全量整理，类似及无法确认项保留；人工审查可选。新策略`illuTag-three-pass-v1`不沿用旧v2的有损建议准入门槛。策略范围、缓存和执行说明见[重复检索](duplicate-search.md)与[三轮规格](duplicate-cascade-design.md)。下述旧版本记录属于历史维护信息。
界面为浅色无框画廊。源码、正式程序/数据、测试工作区应使用不同目录。
1.8.0 标签页采用“结果优先”，大图为沉浸灯箱。仅查看器使用深色画布；主界面继续浅色。缩放、缩略图条分别占位，避免工具条覆盖缩略图。

1.7.0 标签工作台使用顶部分组、封面卡片和右侧组合预览，窄窗将预览放到下方。封面策略、持久化与验证入口见[标签工作台](tag-workbench.md)。
1.7.1 修复卡片滚动，封面要求对应标签置信度≥99%，全局分配唯一图片；仅写小型封面引用，无主库升级、模型任务或图片副本。
整理和撤销只改变已发布结果中的活跃成员；计数和近似直接匹配分组自动同步，不因刷新界面重读原图。新增或实际文件变化仍需手动检查。

1.3.0 增加独立的[重复与近似图片检索](duplicate-search.md)。1.5.0 将重复图片整理改为面向全部已发布扫描结果的自动批次，移除 1.4.0 的逐组保留、勾选和键盘审核流程。
重复检索完成后按完全相同／近似分别整理；人工保留跨组优先，类似与无法确认项保留。查看页可调整保留基准、保护额外图片或明确标记该类待清理项。整理范围不受前端分页或成员展开状态限制。
检索和整理均由用户手动启动。后台分页规划、分批执行，可暂停、停止；统一计划版本变化后旧批次拒绝继续，应按当前结果重新启动整理，原批次成功项仍可撤销。旧单类批次保留兼容续执行能力。默认移入应用回收站，支持整批撤销，原文件暂时保留并继续占用磁盘空间；需要释放空间时另用普通回收站的原文件清理功能。
主库仍为 schema 3，本次没有主库数据库升级。
1.5.1 的整理直接复用已有分组和指纹，候选定位须从 `bulk_members_image(operation,image_pk,group_no)` 驱动保留项查询；不要让 SQLite 从整批保留项驱动，避免数据增长时退化为二次复杂度。状态契约单独提供整理阶段及阶段内进度，实际回收计数与规划计数不得混用。
查重数据属于 `cache/duplicates.sqlite` 派生缓存，可单独清理，不进入完整备份或数据目录迁移包。
批次操作与撤销记录保存在 `operations/duplicate-management.sqlite`，独立于指纹缓存。1.5.0 的全量整理采用磁盘快照与执行游标，日志体积随审计数量增长；旧 1.4.0 交互预览的 32 MiB 预算不再限制全量批次。
记录绑定原主库身份，恢复或替换图库后不能沿用旧撤销；清理记录需要明确确认，不能与活动整理任务同时执行。

### 1.12.3 MIH桶命中与有效候选预算

1.12.2完成候选遍历后报37个范围超限。错误在MIH索引读取阶段：相同16位片段或单bit邻居只是桶命中，旧实现未验证完整64位距离就计入50,000预算。真实现有指纹的只读核对显示部分桶命中超过5万，经过原有完整条件后仅剩几十至几百条。整个任务又在发现任一超限时拒绝发布，因此大量已完成工作无法形成可用新结果。

新版流式验证各路完整哈希距离，再应用既有compare_recall的2%比例／低信息条件，最后计入不同指纹预算。pHash仍使用当前档位距离，dHash仍为距离6且仅在信息量足够时启用；两路并集和去重不变，不额外加入旧compare_near的AND或色彩门槛。原图完整像素、元信息和字节证据标准保持`illuTag-replacement-v2`，有损候选仍不自动回收。过滤后真正超限继续报告未查尽，不发布不完整结果。

候选发现版本为`illuTag-candidates-filtered-v2`并参与断点输入摘要，旧版已走到末尾但含dense的草稿不直接续用；只重建未发布草稿，保留主库、指纹、有效精简证据、人工选择和操作／撤销记录。重跑无需清缓存或强制重算指纹。

这里保留的是两路设计半径和原图证据标准，不是旧版异常的所有输入集合：pHash片段偶然重叠不再绕过完整半径；dHash有效位数不足8或超过56时，不能通过这种偶然重叠绕过既有低信息保护。回归同时覆盖正常两路并集、此边界、50,000预算边界及遍历中的取消。

### 1.12.2 载入指纹时的进度写入互锁

1.12.1把指纹载入放在一个跨全库的`BEGIN DEFERRED`及流式语句内，随后调用进度和控制回调。正式任务回调会写主库`task_runs`；主库使用DELETE日志时，被尚未释放的同一读取事务阻塞，每批等待30秒后进度写失败而旧实现继续运行，界面滞留在最早已保存的阶段。实际线程采样显示`sqlite3_step`／任务记录序列化／`evidence_records_with_progress`调用链；缓存头部只读16毫秒，主库当时读报database is locked。

旧回归使用空进度回调，未覆盖实际任务持久化，因此状态读取和175项回归通过不足以证明完整流程可用。本版新增DELETE日志、双连接真实task_runs写入测试，先确认修复前出现database is locked，再改为每页1000条的整数键分页：销毁statement和reader后才调用任何控制或进度。整次载入以图库成员版本约束，变化时拒绝继续。系统回收物理别名预检同样不得持主库reader调用暂停确认。进度保存失败会终止当前检索并保留提交结果，不能仅输出stderr。

## 空间清理与保留边界

先退出属于该测试或构建的进程，核对完整路径、目录链接和数据用途，再清理。
无需为清理另做整库备份或生成候选包。没有确认归属的共享 npm/Cargo/Python 缓存
不按日期猜删。

| 可清理内容 | 前提或影响 |
|---|---|
| 仓库 `node_modules`、`dist`、`src-tauri/target` 或独立 `CARGO_TARGET_DIR` | 可重新安装/构建；不删除依赖清单、源码或 `.git` |
| 独立测试工作目录的库、日志、截图、WebView、CUDA/Python 缓存 | 已结束相关测试，确认不包含正式数据或仅存源码 |
| 重复候选程序、ZIP、过期发布输出 | 已确认当前正式程序与最终源码保留 |
| `cache/duplicates.sqlite` 及其伴随文件 | 优先使用“重复检索 → 清理查重缓存”；无运行或排队的查重任务，清理后须重新计算 |
| `illutag.schema2.rollback.sqlite`、`storage-program-rollback` | 升级状态为 accepted 且用户决定放弃旧版本恢复；见存储维护说明 |

必须保留正式目录里的当前 `illutag.sqlite`、仍在使用的 WAL/SHM、EXE、模型、运行时、
脚本、配置、偏好、窗口状态、生产 WebView、托管图片及维护状态。外部图库原图不属于
测试产物。源码里的模型 Junction 不是可递归清理的缓存，不沿链接进入正式资源目录。

NTFS 硬链接共享同一文件数据：目录属性中的逻辑大小会重复计算，最后一个链接
删除后才释放物理空间。正式库在生产路径仍存在时，移除其测试链接不会删除正式库。
旧回滚库的测试链接若留下，删掉回滚文件名仍不会释放整块空间。

删除路径应细化到具体缓存或回滚文件，**不能删除整个源码仓库或正式部署目录**。
清理完成只核对目标消失、保留文件存在和磁盘剩余空间，不为验证再次编译、扫描、
打标或复制全库。
