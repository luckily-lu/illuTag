# 三轮重复图片检索与整理

“重复检索”手动启动一次，连续完成宽筛、内容筛选和严格像素确认。结果分为完全相同、近似、类似及无法确认；检索本身不回收图片。当前策略为 `illuTag-three-pass-v1`，主库保持 schema 3。

## 使用流程

1. 打开“重复检索”，点击“开始三轮检索”。默认复用有效指纹；新增或变更图片后可再次检索。
2. 查看三轮进度及各类结果。每类“查看”均打开真实分组，可同时浏览成员和放大原图。
3. 完全相同与近似各有独立的“一键整理”。近似可先人工查看、指定保留基准或额外保留，人工审查不是批量整理的前置步骤。类似与无法确认项默认保留。
4. 整理覆盖该类别全部已发布结果，不受当前分页或已展开成员限制；仅移入应用回收站，支持暂停、停止和整批撤销。原文件暂时保留，不会因此释放磁盘空间。

人工调整只修改整理计划，不立即回收图片。指定基准和人工保护优先；更新指纹、整理或撤销期间暂不可修改，但仍可浏览已有结果。完成指纹更新进入三轮筛选后，可调整上次完整结果，最终发布会合并最新选择。

## 三轮如何分类

| 轮次 | 输入与处理 | 输出 |
| --- | --- | --- |
| 1 宽筛候选 | 全库有效指纹，以较宽的 pHash／dHash 范围找到可能有关的图片 | 包括完全相同、近似及细节不同的候选图片池；不是可删除清单 |
| 2 收紧内容差异 | 仅在首轮候选池中比较原图内容，实际通过才覆盖成员；失败成员仍可寻找自己的副本 | 完全相同与近似候选；取得差异证据的类似图；证据不足的无法确认项 |
| 3 严格确认相同 | 对第二轮通过项核对原生尺寸和全部像素样本 | 完全相同；未满足严格标准但通过内容容差的近似图 |

类别表示图片与参考图的关系。一个分组的成员不一定彼此近似，一张图片也可能出现在多个上下文中。各类图片数和组数不能相加；“可整理”数量来自该类计划的唯一目标，不是候选对数或分组内所有图片数。

完全相同使用独立组件计划，每组件至少保留一张，保护项优先；不会因为组件中的图片也匹配另一张更大的近似图，就让“完全相同”按钮失去自己的整理范围。近似使用全局保留计划，按像素面积、文件大小等稳定顺序选择保留者，每个回收目标必须直接通过与最终保留者的验证。面积与文件大小用于排序，不证明真实画质更好。近似关系不传递，不沿 A—B—C 相似链回收 C。

## 当前判断边界

**完全相同**要求校正 EXIF 朝向后的原生尺寸及每个像素样本一致。8 位与 16 位仅作精确的 257 倍映射；透明度、透明像素下的颜色及低位都参与严格比较，不缩小、不白底合成、不丢精度。原文件字节完全一致也可直接证明相同。文件名、编码方式、元信息和附加非像素数据不同，不会单独阻止严格像素相同的图片进入此类。

**近似**允许重新压缩、等比例缩放及有限轻微色差，不要求原生像素逐值一致。比较在较小原图的分辨率进行，尝试有限的全图重采样，并检查多个尺度的像素和局部边缘差异。尺寸比例差不超过 0.2%，单边分辨率差最多 4 倍；较小图短边至少 64、长边至少 256。RGBA 近似还要求 alpha 逐值一致。当前容差不等于语义判断，极小改动或缩小后消失的细节可能无法区分；近似保留人工查看和调整入口。

**类似**表示取得了不满足当前近似容差的内容差异证据，默认保留。**无法确认**单独承接来源离线、读取或解码失败、源变化、分辨率不足及超出支持范围等情况，不把这些失败当作内容变体。

原图像素验证支持静态 PNG／JPEG／BMP／WebP 的 8／16 位样本。GIF、动画 WebP、APNG、多页 TIFF／ICO／AVIF 和浮点容器只走已支持的原文件字节相同路径，其余无法确认。原生解码上限为 16MP、64MiB 单图分配，超限保留。裁剪、水印、镜像、旋转、局部形变和任意调色不作为本轮自动吸收目标。

## 索引、缓存与任务

首轮固定使用 pHash 距离不超过 8 或有效 dHash 距离不超过 8 的召回并集，宽高比相对差不超过 2%；低信息图仅进入完整特征与尺寸一致的窄范围。使用有界分段索引，桶初步命中须经过完整数值条件过滤后才计入候选预算。

首轮压缩同指纹范围并保存宽筛星，不建立全库两两矩阵。第二轮从候选池重新定位直接关系，只有实际原图验证通过才覆盖成员；字节内容单元展开时，每个实际目标仍验证自己的最终保留关系。第三轮还使用原生 RGBA16 摘要寻找近似星内部的严格副本，摘要命中后仍逐像素核对，不能仅凭摘要回收。无需展开的候选边不冒充已确认差异，实际展开的关系数量也不是理论两两组合数。

指纹、分组和版本化验证结论位于可重建的 `<data_dir>/cache/duplicates.sqlite`。结论绑定两端身份、源签名、SHA 和算法版本；源或版本变化后失效。无法确认不作为永久否定缓存。整理与撤销日志独立保存在 `<data_dir>/operations/duplicate-management.sqlite`；恢复包与数据目录迁移不携带查重缓存。

首轮和第二轮分别保存游标及覆盖集合。停止或重启后由用户重新运行，兼容的输入与内容单元布局可继续草稿；未提交的小批或当前参考图可能重做。完整新结果发布前，保留上次完整结果与已提交验证，不能把未查尽阶段显示为完成。候选过密、磁盘不足或预算耗尽会停止并说明原因，不发布不完整结果。

磁盘缓存预算按图库规模增长：512MiB 基础额加每张缓存图片2KiB、按64MiB取整，绝对上限8GiB，同时给磁盘至少保留2GiB空闲。约84万条指纹时允许约2.125GiB，这只是上限，不会预先占用这些空间；与512MiB工作内存预算独立。页上限、日志及写入余量由同一策略配置，回收后的空闲页会复用，新结果完整发布后再分批淘汰旧版验证数据。读取语句结束后才保存任务进度或响应暂停，计算与暂停不持长写事务。页面读取失败可重试读取已保存结果，不自动启动新检索或整理。源、成员、人工选择或结果版本变化后，旧整理预览不能继续，原批次成功项仍可撤销。

文件内容发生变化但大小、修改时间被保留时，可在“更多”中勾选“强制重新计算指纹”，再重新三轮检索。清查重缓存与清整理记录是不同操作：前者不能删除原图或撤销日志，后者清除后不能再通过那些批次撤销，需要确认。

## 旧版结果

1.11.0—1.12.3 的 `illuTag-replacement-v2`“可回收／保留”统一流程及“有损仅作建议”属于历史策略，不作为当前三轮分类或整理入口。页面遇到旧策略会要求重新三轮检索；有效指纹可复用，但旧分类和任务断点不能冒充新三轮完成。图片 ID、标签、分类、收藏、来源、人工保护及已有整理撤销记录保留。
