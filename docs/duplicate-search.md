# 重复与近似图片检索

illuTag 1.3.0 的“重复检索”用于检查全图库的文件副本与近似画面。它只提供检索和原图比对，
不会删除、合并图片，也不会折叠普通图库。图片 ID、标签、分类、收藏及历史引用保持不变。
应用回收站中的图片默认不参与检索；本功能没有单张图片检索入口。

## 使用方法

1. 在左栏工具区打开“重复检索”，点击“开始查重”。首次检查需要读取原图，耗时取决于图库规模、
   来源磁盘及图片大小；不会在启动应用或进入页面时自动运行，也不属于“一键处理”流水线。
2. 使用“全部／文件完全相同／近似候选”筛选结果。每页读取 20 组，每组先显示 6 张（包含参考图）；
   “展开更多图片”每次追加 50 张，大组和更多分组均按需读取。
3. 点击候选图与参考图比对。两张原图可分别使用滚轮、按钮缩放及拖动平移；“适应”恢复完整画面。
   窄窗改为上下排列。Esc 关闭比对后，返回原分组位置和打开按钮的焦点。
4. 默认使用“标准”近似筛选。切换到“严格”或“宽松”后，点击“重新检索”应用新条件。
   有效索引只需重新分组；若索引已失效或勾选了强制重算，则先更新指纹。
5. 新增、删除、扫描或源文件变化后，使用“更新结果”。在“任务中心”可暂停、继续或取消；
   切换页面不会停止任务。取消保留已提交的指纹，重跑复用有效结果。

页面显示覆盖量、失败数量、近似检查跳过数量、低信息及过密数量、检查时间、上次实际用时、缓存体积和最近一次任务。
重启后的未完成任务显示为“已中断”，需要手动重新运行，不承诺跨重启精确续传。

## 如何理解结果

**文件完全相同**：按原文件大小和流式 SHA-256 分组。改名或跨目录复制不会改变结果；
仅修改元信息也会改变文件字节，不能标为文件完全相同。

**近似候选**：将静态图片校正 EXIF 朝向、透明部分合成到白底后，比较 pHash、dHash、
4×4 RGB 色彩摘要及宽高比。用于发现重新压缩、等比例缩放和轻微色差的画面；
裁剪、水印、镜像和旋转版本不作为第一版的检索目标。

| 档位 | pHash 汉明距离上限 | dHash 汉明距离上限 | RGB 平均差上限 |
| --- | ---: | ---: | ---: |
| 严格 | 2 | 8 | 16 / 255 |
| 标准 | 4 | 12 | 24 / 255 |
| 宽松 | 6 | 16 | 32 / 255 |

三档均要求宽高比相对差不超过 2%。这些数值只是候选筛选条件，**不是相似百分比，也不是已经确认同图**。
原图比对中展示成员与参考图的距离指标，最终判断由用户完成。

近似组是以参考图为中心的分组：每个成员都直接匹配参考图，但成员之间未必相似。
检索不会通过成员继续扩展成传递关系；桥接图片可出现在多个组中。参考图按像素面积、文件大小和
图片 ID 的稳定顺序选择。同一 SHA-256 的副本先形成内容单元，减少重复比较。

以下范围不进行普通近似分组，读取成功时仍保留文件完全相同检查：

- 动态 GIF／WebP：不以第一帧相同判断动态图重复；单帧静态文件可参与近似检查。
- 超过 32 百万像素、超过解码内存限制或无法解码的图片：显示近似跳过数量。
- 近纯色等低信息图片：避免把缺乏画面信息的文件聚成大量近似组。
- 单参考图超过 50,000 个不同指纹候选：跳过该参考图的近似分组并标为过密，结果显示部分完成。

来源盘离线、权限不足或文件在读取过程中变化会显示错误，而非宣称全库完成；无法读取原文件时也无法做
文件哈希检查。已有完整结果不会被取消、失败或部分完成的任务覆盖；首次没有完整结果时，已生成的分组可
标为“部分完成”展示。请结合覆盖量和最近一次任务状态判断结果，不能仅凭空列表确认没有重复图片。

## 缓存与数据边界

指纹和分组保存在数据目录下的 `cache/duplicates.sqlite`，是可重建的派生缓存。
主库继续使用 [schema 3](storage-schema3.md)，不进行全库复制、主库迁移或更新既有 `content_hash`。
查重索引仅按需加载，默认使用一个解码工作线程。

缓存核对内部图片键、公共 ID、源文件身份、大小、修改时间及算法版本 `illuTag-duplicate-v1`。
Windows 文件身份使用卷号与文件 ID，能识别同路径被另一个副本替换的情况；主库路径和文件身份也会校验。
若在同一个文件内修改内容并保留大小、修改时间及文件身份，勾选“强制重新计算”重新读取原图。
标签、分类或收藏变化不要求重新计算图片指纹。

缓存及其 WAL／日志等伴随文件合计预算为 512 MiB，索引新增内存目标不超过 512 MiB；
缓存所在磁盘至少保留 2 GiB 空闲。达到预算会停止并报告部分完成，保留已提交指纹及上一次完整结果。
这不是整个应用的内存上限，图片浏览和其他索引另有开销。

“清理查重缓存”只清理查重数据库及伴随文件，不删除原图、缩略图、主数据库或其他运行资源。
有查重任务运行、暂停或排队时先取消任务，再清理。下一次检查需要重新读取原图。
完整备份和数据目录迁移不携带查重缓存；恢复、迁移、主库替换或算法版本变化后需要重新建立有效索引。
更多备份及隔离测试要求见 [维护指南](maintenance.md)。

## 验证记录与实测边界

2026-10-14 的前端类型检查及 21 项 Vitest 测试通过，其中 12 项覆盖查重状态、过期分页响应、
任务终态刷新、独立缩放和 Esc／焦点行为。任务进度只更新任务行，不周期性重载图库或查重分组。

浏览器使用明确标识的虚构样例完成 500、768、1024、1280、1920 CSS px 宽度检查，
验证分组／成员分页、筛选、待应用档位、缓存清理、空／过期／部分／无效状态、独立图片比对和滚动位置恢复。
500×500 窗口中的超长图保持完整比例，控制栏可达，没有横向溢出。
第二轮真实 Tauri／WebView2 验收的 12 项检查通过，使用 211 张合成素材，合计 1,343,233 字节。
覆盖真实来源登记与手动扫描、完全相同与近似候选、原图比对、严格档位重分组、实际成员分页、暂停／取消、
正常关闭后重启中断、解码跳过、缓存清理，以及主库图片、标签、`content_hash` 和 schema 3 完整性。

Rust 常规测试通过 75 项库测试和 4 项程序测试；默认忽略的 80 万条 MIH 规模测试另行显式运行通过，
合计 80 项。规模测试中 MIH 数值索引结构为 23,448,592 字节，完整分组内存估算为 400,777,216 字节。
前者是合成索引结构大小，后者是算法预算估算，都不等同于真实应用进程的峰值内存。

本次真实图库共有 832,758 张图片，首次实测约 447 秒内已提交 45,900 张有效指纹，
保留的派生缓存约 12.33 MiB。按用户要求，实测已停止，已提交的指纹保留供后续手动更新复用。
**全库指纹、完整分组、总耗时及真实峰值内存尚未验收**；不能将这段实测或合成规模测试表述为全库验证完成，
也不能直接据此承诺全库运行时间。
