# 任务中心与浏览快捷操作

## 页面与控制

1.12.0 将任务中心分为当前任务、等待队列和历史记录。一键处理及独立任务入口放在顶部。来源范围、阶段、进度单位和后台提供的控制能力随任务记录显示。

重任务使用单个 FIFO 队列。暂停请求先显示“正在暂停”，执行器到达安全点才确认“已暂停”；暂停的任务继续占用执行位，后续队列等待。停止后保留已经提交的结果。取消等待项直接移出队列，不会随后偷偷执行。不可暂停的维护阶段不显示暂停按钮。

处理结束后若终态保存失败，队列停止领取后续任务，当前任务显示“结果待保存”。“重试保存”只提交原来的结束结果，不重新读取图片或执行任务；即使重复点击，也不会创建第二次处理。

历史按状态筛选，每页20条，游标由后端返回。详情保留原请求的来源、缩略图偏好、处理提示和时间。普通历史任务的“重新运行”完整重放原请求；回收批次的“继续原批次”沿用原操作编号并重新校验可执行性，不重新扩张选择范围。

1.12.1起耗时只使用实际开始／结束时间；旧终态记录缺失时间时显示“未记录”，不能拿现在的时间减任务ID。重启中断的结束边界使用上次提交时间，不计应用关闭期间。

清除历史需要二次确认，只清终态任务记录，不删图片、活动任务、排队项或独立回收操作日志。该操作不可撤销。

## 持久化与事件

- 继续使用主库schema 3的`task_runs`，增加查询索引及可选的JSON元信息，不迁移或复制主库。收藏标签复用`app_meta`，同样无需数据库升级。
- 任务状态、持久化、事件发布在统一提交边界协调。普通状态先保存再发布；保存失败提示是明确标识的运行时附加状态，不能伪装成已经保存的完成状态。
- 每个任务带递增revision和能力字段；旧进度、迟到快照不能覆盖新状态，终态不能退回活动状态。重试产生新任务ID，批次操作编号保持原值。
- 运行时只持有活动项与最近100条终态；历史使用数据库分页，不将全部历史常驻内存。启动时将全部未完成记录标为已中断，不自动开始任何图片处理，由用户自行重新运行。
- `start_job`、`control_job`、`retry_job`、`job_history`、`clear_job_history`统一走IPC；Rust DTO由ts-rs生成。`retrySave`是`control_job`的专用幂等动作。

## 看图删除

沉浸灯箱工具栏提供删除按钮，Delete将当前图移入应用回收站，不弹确认、不删除原文件。保留当前范围、标签组合和顺序，自动看下一张；最后一张回到上一张，无图则关闭。加载边界先尝试续页；续页失败保留错误提示与可用图片。

Ctrl+Z或提示中的“撤销”还原最近一次看图删除，恢复在原列表的位置。撤销仅在该图片仍处于本次回收状态、图库尚无后续图片变更时允许，防止覆盖其他操作；不满足时可到应用回收站还原。撤销记录只保留在当前应用会话，不跨重启。

输入标签、编辑文字、下拉菜单和弹窗打开时不响应看图删除。长按Delete、重复请求和迟到响应不会误删下一张。应用回收站的只读看图不提供此删除入口。

## 标签收藏与导航

主导航顺序为全部、随机、标签、收藏、待分类、回收站；此处“收藏”是图片收藏。标签页里的心形按钮收藏标签，顶部分组固定提供“收藏”，二者独立。

收藏标签用英文原名作为稳定键，中文译名变化不丢失收藏；可继续按分组、关键词、数量和排序浏览，并加入组合条件。收藏操作不会选中或取消搜索条件，也不改变标签封面。小型引用随现有完整SQLite备份保存，不生成图片副本。
